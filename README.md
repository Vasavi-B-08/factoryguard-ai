# FactoryGuard

Industrial machine monitoring and predictive-maintenance dashboard prototype, built for an
AMD engineer workflow: monitor machines, inspect sensor readings, review failure analysis,
and ask an AI technician for troubleshooting help.

> **Demo mode.** Every machine, alert, sensor history, analysis result and technician reply is
> clearly labelled sample data. No network calls are made. The data layer is isolated behind a
> single service adapter so a backend can be connected without redesigning the UI.

## Tech stack

- TanStack Start v1 (React 19, file-based routing, SSR)
- TypeScript, Vite 8
- Tailwind CSS v4 (semantic design tokens in `src/styles.css`)
- shadcn/ui primitives, Recharts, lucide-react
- Vitest + Testing Library

## Getting started

```sh
npm i        # or: bun install
npm run dev  # http://localhost:8080
```

Other scripts:

```sh
npm run build      # production build
npm run preview    # serve the production build
npm run test       # vitest run
npm run lint       # eslint
npm run format     # prettier --write
```

## Pages

| Route | View |
| --- | --- |
| `/` | Overview — fleet health, KPIs, attention list, sensor charts |
| `/machines` | Searchable and filterable machine inventory |
| `/machines/:machineId` | Machine detail — live-style sensor panels, history, related alerts |
| `/alerts` | Alert feed with severity, acknowledgement and status filters |
| `/analysis` | Sample failure analysis: probable cause, evidence, recommended actions |
| `/technician` | AI technician chat transcript (fixed demo replies) |
| `/settings` | Display preferences (units, theme), stored in the browser only |

## Project structure

```text
src/
  data/         Sample records: machines, alerts, sensors, analysis, technician replies
  services/     api.ts — the single adapter the UI talks to (demo mode today)
  features/     One module per workspace view (overview, machines, alerts, analysis, technician, settings)
  components/
    factoryguard/  Shared app UI: shell, machine table, charts, panels, state helpers
    ui/            shadcn/ui primitives
    ai-elements/   Chat transcript + composer primitives
  routes/       File-based routes (TanStack Start); __root.tsx is the app shell
  hooks/ lib/   Small shared utilities
```

### Connecting a real backend

`src/services/api.ts` exposes one `api` object (`listMachines`, `getMachine`, `listAlerts`,
`getHistory`, `analyze`, `chat`) plus an `apiConfig` with the proposed endpoint paths. Views only
consume this adapter, so switching from demo data to HTTP means changing the handler bodies in
that one file — no view redesign required.

Status classification and health thresholds are not computed in the UI: they come from the data
records, so production values must be supplied by the backend.

## Notes

- Display preferences live in browser storage only; alert edits and the single demo conversation
  are session state. No database or auth is wired up.
- `src/routeTree.gen.ts` is generated by the router plugin — do not edit it by hand.
- This is a frontend prototype: nothing here is production monitoring.
